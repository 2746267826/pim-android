# 本地混合文档与基础手写

关联 [总路线图](https://github.com/2746267826/pim-api/blob/master/docs/product/native-notes-roadmap.md)、
[总 epic #505](https://github.com/2746267826/pim-api/issues/505) 和 [本片 #35](https://github.com/2746267826/pim-android/issues/35)。
本片基于尚未合并的录音 PR #34 (`cf09bbc26119`)，master 基线仍为 `9941ce411740`。
向 master 开 PR 时会暂时包含前置提交，合并次序必须先处理 #34；没有自动合并或绕过 CI。

这是原生本地预览版，不是 M1+M2 完整首版。没有上传、ASR、AI、云端输入快照或跨端同步，
不以本地 revision 冒充服务端版本保护。首版手写仍为必交，Windows 记录和 Web 继续保留在唯一总路线图。

## 如何体验

1. 主应用“今日”顶部打开“本机笔记 · 本地预览版”，新建一条记录。无需账号或服务器。
2. 输入标题和普通 Markdown；“预览/编辑”切换使用 Markwon，不是自制 Markdown 解析器或所见即所得富文本编辑器。
3. 将光标放在希望插入的位置，选择“拍照”“照片”或“手写”。前后文字不删除，材料位于两者之间。
4. 手写卡片点击“书写”，用手指或系统识别的手写笔输入；“仅手写笔”模式忽略手指，
   不等于保证所有厂商掌触都能正确识别。“整笔擦除”删除碰到的整条笔迹，不是像素橡皮。
   当前页面支持撤销编辑；重开后仍能移除末笔、继续写或擦除，不承诺跨重启撤销历史。
5. 拖右下角直接改变宽高。拉大增加空白，缩小至笔迹边界，不裁掉或分别拉伸笔迹。
   在更窄窗口统一缩放整卡片以适应正文宽度；数据使用文档逻辑坐标，不按机型写死。
6. “录音”必须单独点击、授权；新建/输入/恢复草稿不会开麦。左下紧凑条显示真实采集，
   通知返回原条目，打开另一篇不会改绑录音。结束后可在同篇补录；音频归属落在录音清单中。
7. 右上“结束”先等待录音停止，再保存本机。保存失败显示失败和重试，不显示假的上传或分析完成。
   尚未保存时不要强制停止应用；普通离开页面不撤销应用级保存任务，也不会自动停止正在录的音。
8. 更多菜单“导出文档包（不含录音）”导出 ZIP，含普通 Markdown、可编辑清单、照片和手写 PNG。
   不含录音，不是整篇记录的完整备份或云提交包；尚无导入 UI。目标写入失败可能留下不完整 ZIP，
   会明确报错，不删除原材料。此片没有删除记录/清理原文件的功能。

请只在获得录音同意的场景使用。不要把个人课堂、会议或研究原材料放进 issue、PR 或诊断包。

## 数据与安全边界

- 私有 `noBackupFilesDir/notes/<UUID>/note.json` 是原稿：版本号、标题、严格有序块列表。
  Markdown 叶块保留精确源码；照片块保留身份、MIME、SHA-256，笔迹块包含宽高及压力/坐标序列。
  未知顶层属性/块载荷原样保留；不支持的新 schema 或损坏文件显示不可读，禁止空白覆盖。
- 混合文档不是一份能被任意 Markdown 编辑器无损反推的文本：每个 Markdown 叶块独立解析，
  材料是块边界，跨材料的未闭合代码围栏/列表等不承诺保持跨块语法。
  `document.md` 是通用阅读投影，`note.json` 才保留可编辑材料的身份/顺序/尺寸；
  不宣称单个 Markdown 文件导入或其他平台编辑器往返已经实现。
- PNG 从原始向量派生，文件名包含笔迹内容摘要；改笔迹产生新图，不覆盖旧版本图。
  导出从原稿重建对应派生图，不能把损坏缓存当成原稿。使用中性纸面与统一蓝色语义。
  页面使用 `PimTheme` 与已有基础组件，不散写色号。
- 文档保存使用 `AtomicFile` 和文件同步；后台单写入队列保留最新修订，拒绝陈旧/同号不同内容覆盖。
  先完成派生图，再原子切换可编辑清单；进程中断仍可能丢掉尚未显示“已保存”的更改。
- 照片先校验后插入，保留 JPEG/PNG/WebP 原字节（含原有 EXIF），预览按 EXIF 转向并降采样。
  当前单张导入限制 32 MB，不静默裁剪原图。该限制是本地安全边界，不是未来服务器配额。
- 相机使用独立非导出 `NotesCameraProvider`，只开放 `cache/note-camera/` 中的一次性输出 URI；
  返回后撤销授权，成功导入才清理暂存，取消不会插入占位图；不开放 `noBackupFilesDir` 或诊断目录。
  捕获锚点保存在 `SavedStateHandle`，不因 Activity 重建改插到别篇。导入失败的临时/孤立材料不主动清除；
  冷启动结果必须等待目标文档加载，不得在未插入块时误报成功并清理相机原件。
  系统仍可能回收 cache，本片没有完成遗留暂存材料的恢复管理。
- 渲染不装网络图片插件，链接不自动打开，不上传原稿、照片或音频；键盘个性化训练与 autofill 请求关闭。
  系统/第三方键盘仍是用户选用的输入法，不能因此声称完全防止设备侧读取。
- 文档包内引用为 `assets/` 相对路径；缺材料或未知扩展阻止“完整文档”导出。
  导出前核对照片原字节摘要；文件仍存在但内容损坏时也不报完整导出。
  导出固定点击时的内存文档快照，不覆盖后来保存的本地稿；音频在独立录音清单中，明确不导出。
  尚未做账户归属/配额/云端材料保留，不自动把本地记录上传到当前登录账户。

## 验证方法与边界

```powershell
.\gradlew.bat :app:testDebugUnitTest :app:assembleDebug :app:assembleDebugAndroidTest :app:assembleRelease --no-daemon --max-workers=4
$env:ANDROID_SERIAL='<isolated-emulator-serial>'
.\gradlew.bat :app:connectedDebugAndroidTest '-Pandroid.testInstrumentationRunnerArguments.class=com.pim.app.notes.NativeNotesDocumentTest,com.pim.app.recording.RecordingCaptureTest,com.pim.app.ui.theme.PimThemeComponentsTest,com.pim.app.ui.today.TodayScreenTest' --no-daemon --max-workers=4
```

具体执行数量、修订与结果以本批 PR 为准；代码存在和编译通过不等于设备验收。
隔离模拟器禁用宿主音频，相机是模拟场景；验证实际 Android 管线，不验证真实语音质量或 OPPO 笔输入。
照片结果导入测试与真实系统相机流程须分别标记，不将注入结果称为已经打开摄像头。

仍未验收：OPPO 两台设备的笔/掌触/滚动/拍照共录，100/180 分钟及超段实测，
存储耗尽、真实掉电和厂商杀进程，超长正文/大量笔迹性能与可访问性，
包导入及 Windows/Web 一致性，以及完整材料版本、长附件提交、ASR/AI 与六条修改冲突规则。
