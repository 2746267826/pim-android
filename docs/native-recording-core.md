# 原生录音内核与 M0 验证

关联 [完整路线图](https://github.com/2746267826/pim-api/blob/master/docs/product/native-notes-roadmap.md)、
[总跟踪 #505](https://github.com/2746267826/pim-api/issues/505) 和 [录音切片 #33](https://github.com/2746267826/pim-android/issues/33)。
实施基线是合并主题 PR #32 后的 `origin/master`：`9941ce4117407ccf1c98c68bad111f999e15c8ad`。

这是可复用的真实录音内核，不是笔记首版。验证入口只存在于 debug 源集，release 没有该 Activity，
设置中的入口也只在可调试包显示。基础手写仍必须随首个安卓可用版交付；正文/照片/笔迹、长材料提交、
ASR/AI、结果修订与多端冲突仍由完整路线图约束，没有用假按钮或模拟上传补齐。

## 如何体验

1. 在隔离测试设备安装 debug 包，打开设置的“诊断”区块，进入“录音可靠性验证（开发中）”。
2. 点击“开始真实录音”，明确授予麦克风权限；系统通知权限被拒绝或渠道被关闭时，页面如实提醒状态可能不可见。
3. 左下紧凑条展示实际输入峰值、当前用户段及已采集时长；暂停/继续可从条内或通知操作。
4. 锁屏或切应用后观察持续通知；结束操作先完成本地文件与清单保存，成功才显示“本地保存完成，未上传”。
5. 在本机记录中回放全部用户段；内部分片依次播放，回放不承诺无缝接缝。采集中不允许回放，以免反馈干扰输入。

仅在有参与者录音同意的场景使用。验证不要求账号或服务器，也不把音频交给既有同步、诊断导出或 ASR。
模拟器测试使用禁用宿主音频的专用 AVD，不收集电脑麦克风内容；它证明管线可运行，不证明声学质量。

## 实现边界

- `RecordingService` 是独立、非导出的 microphone 前台服务，只有前台页面的显式用户操作开始录音。
  返回 `START_NOT_STICKY`；应用启动、开机和草稿恢复不会重新开启麦克风。与定位服务、WorkManager 分离。
- `AndroidPcmInput` 使用真实 `AudioRecord`，16 kHz、单声道、16-bit PCM；波形来自实际样本峰值，
  没有输入时不制作装饰动画。非阻塞读取避免取消和无输入超时依赖音源返回；支持的平台上监听系统静音状态。
  读错误、连续约五秒没有样本或明确静音会结束为中断，不自动抢回麦克风；静音 PCM 样本仍是实际采集，不等于无样本。
- `RecordingEngine` 按实际样本计时，不依赖墙上时钟或页面存活；暂停不增加时间。单用户段 3 小时，
  达到边界后的样本进入同次记录的下一段；同次记录无另设累计时长上限，实际存储/电量仍有限。
- 内部约一分钟一个 WAV 文件，写满内部分片或切用户段不重启麦克风。每约一秒更新 WAV 头、同步文件及原子清单。
  文件位于应用私有 `noBackupFilesDir/recordings/<UUID>/`，不进系统备份，不包含凭据。
- WAV 原始 PCM 便于进程中断后按实际文件长度恢复头部，不依赖结束时的编码器封装。代价约 115 MB/小时
  （100 分钟约 192 MB，3 小时约 346 MB，按十进制估算）；未来压缩/上传方案须另行验证，不能静默清理原文件。
- 冷启动验证页将上次录音/暂停标为已中断，修复可读音频头，不自动继续录音。损坏清单仍显示材料存在；
  缺失文件的关联不丢弃，损坏文件不冒充成功，也不覆盖或删除原音频。数据不支持降级伪装成完整记录。
- 采集中持有局部唤醒锁，暂停/结束/异常释放；通知 ID/渠道与定位独立。通知只显示通用状态、段号和时长，
  锁屏公开版本不暴露材料身份或内容。旧通知操作带会话校验，不能停止后续另一条录音。
- 不申请跨应用悬浮窗。紧凑条、颜色、形状、触控目标和波形尺寸沿用 `PimTheme`，采集不依赖该组件存活。

## 验证与未决项

本地单测验证 PCM 字节、分片/跨段、暂停计时、真实峰值、WAV/清单恢复、损坏保全、权限与通知边界。
设备侧测试必须实际运行，覆盖真实采集、退后台/息屏、暂停与通知继续、结束及系统解封装读取，
并验证无活动录音时的“继续”不会开麦、页面重建不会把进行中的会话误恢复为中断。
执行结果以 PR 对应修订为准，不拿源码或编译结果冒充运行通过。

在已配置 JDK/Android SDK 的 `src/client-android` 目录可运行：

```powershell
.\gradlew.bat :app:testDebugUnitTest :app:assembleDebug :app:assembleDebugAndroidTest :app:assembleRelease --no-daemon --max-workers=4
$env:ANDROID_SERIAL='<isolated-emulator-serial>'
.\gradlew.bat :app:connectedDebugAndroidTest '-Pandroid.testInstrumentationRunnerArguments.class=com.pim.app.recording.RecordingCaptureTest,com.pim.app.ui.theme.PimThemeComponentsTest,com.pim.app.ui.today.TodayScreenTest' --no-daemon --max-workers=4
```

录音新增 17 项单测；设备回归为录音 4 项、主题组件 6 项和今日状态 2 项。
专用 AVD 使用 `-no-audio`，不得把这类测试描述为真人语音识别或声学质量验证。

以下仍未验收，不能从模拟器或加速边界测试推断通过：

- OPPO Find X9 Pro / Pad 4 Pro 的实际系统版本、后台限制、锁屏通知权限/可见性。
- 真实 100/180 分钟和多段超 180 分钟的连续性、电量、温度、存储与录音质量。
- 真机来电、其他应用占麦、撤销权限、空间耗尽、强停/重启、厂商杀进程和掉电后的保全。
- 拍照与采集共存、手写/掌触/正文滚动、完整混合编辑器和用户材料的版本保护。

强停、重启或系统终止不能保证继续采集，已同步前缀之外也不能承诺零丢样；需要展示中断并保留材料。
M0 内核验证不是 M1/M2 安卓可用版的完成声明。
