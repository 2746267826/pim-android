# 正式笔记入口与固定材料上传

本切片对应 NOTE-01/04/05、REC-04、SYNC-01/02、SAFE-01 和 NATIVE-01 的部分范围。完整目标与剩余项仍以 `pim-api/docs/product/native-notes-roadmap.md` 为唯一总台账；本切片不交付安卓转写、完整记录或独立分析。

## 用户路径

主导航提供“今日、笔记、更多、设置”。定位、轨迹、日程和状态保留在“更多”；宽窗口使用侧栏。笔记库读取既有本机数据，可按标题或 Markdown 正文搜索，新建/打开继续使用已有原生宿主、离线编辑、照片、向量手写与录音层，不复制另一套原稿。

结束记录后先准备本机固定版本。用户从“材料版本与上传”选择具体版本，核对账号、服务器和材料范围并明确同意，才保存上传意图。原照片可能带 EXIF，录音、照片与可编辑笔迹均保留。此后的编辑/补录不改变上传输入。上传只保存服务器材料，不自动发起收费模型调用。页面重建会重新要求确认，不沿用旧页面的同意。

材料页与笔记库分别显示排队、上传进度、等待确认、暂停、原账号登录、失败、服务器完整接收或版本冲突。只有服务器确认完整版本才显示接收成功；本机保存、已传字节和转写/分析完成不是同一状态。

## 身份和传输边界

- 登录和刷新从真实鉴权回复的 `user` 保存稳定 owner ID/名称，与令牌一同进入原有加密存储。不把未经验证的 JWT 解码结果当身份。旧会话缺 owner 时可继续原有功能，但需重新登录才能确认上传。
- 任务只保存 owner、固定服务器、版本/清单摘要、已知基础版本与进度；WorkData 只放任务 ID，令牌不进队列、材料清单、导出或日志。
- 固定目标客户端在实际附加首个和401重试认证头时，在服务器设置锁内读取同一个不可变 owner/token 快照；切账号/服务器/退出即暂停旧意图，不改用新账号令牌。
- 刷新结果不能更换 owner；迟到刷新或失败清除以原快照为比较条件，不能覆盖/清除较晚登录的账号。绑定客户端禁止重定向和任意非笔记路径。
- 服务器地址沿用当前仅支持 `/api/v1/` 的规范，不新增其他部署根路径支持。

## 持久上传与恢复

`noBackupFilesDir/note-uploads` 保存原子检查点并读回确认。应用重开只续作已同意的排队任务，不因登录或本机版本齐备就自动创建上传。缺损任务保留并提示，其余任务可以继续。

每轮根据服务器回执核对同一版本的路径/种类/大小/摘要和已存分块，最多读取1MiB数据。成功回执丢失后重开同一版本，跳过已存块；完成回执未知时先核对原版本，不假称成功或新建版本。源摘要和版本元数据不一致时停止，不读当前新稿替代。

每个worker在32个新分块或约两分钟后让出，后继继续同一意图；网络/服务器暂时失败使用指数退避并尊重 Retry-After，连续实际失败最多八次后由用户明确恢复。正常分批和服务器要求的等待不作为网络失败计数。手动恢复替换旧排程，同任务执行互斥，避免取消/重试重叠。

普通服务器目标沿用 WorkManager `CONNECTED` 条件；字面回环地址 `127.0.0.1`/`::1` 不依赖公网，使用 `NOT_REQUIRED`，仍执行相同身份和协议校验。见 [AndroidX NetworkType](https://developer.android.com/reference/androidx/work/NetworkType)。真实无公网局域网、Doze/OEM省电和长时传输仍需目标环境验收。

## 版本与冲突

基础版本只取同账号/服务器下本机已确认的上一上传，不在后台悄悄改成远端最新头。服务端发现其他修改时保留双方完整材料并显示冲突，不自动提升或覆盖；跨端对比/选择、人工结果修订与重生成防覆盖仍是后续范围。

## 本批边界

新接口全部来自已合并唯一契约，由既有脚本生成类型并通过编译期检查。没有新增手写远端 DTO、后端路径、SDK或依赖升级。

当前使用已有 Material3 导航和窗口宽度分支，不把它记成 Material3 Adaptive 库、BOM升级、参考字体或Lottie已经接入。全局撤销/长文性能、普通账号ASR授权、全材料双产物和修订/冲突产品UI、真实后台崩溃/重启和OPPO100/180分钟/笔输入仍保持开放。当前最多保留256个上传意图，归档/清理尚未提供产品入口；单版本容量/过期及配额以服务器回执为准。

验证必须区分纯单测、合成HTTP、真实Test API/模拟器及真实设备/课堂。实际执行结果、准确提交和失败历史见本切片PR；不把测试代码存在、构建成功或模拟器素材当成课堂质量验收。
