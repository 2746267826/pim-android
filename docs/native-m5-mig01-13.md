missing, what this wave added, and the honest Web-only boundary that remains. A
row is not considered migrated merely because it can render data or open a
WebView.

## Contract policy

- Every new call uses an operation already present in `contract/openapi.json`.
- `scripts/contract/client-operations.json` was extended and
  `ContractModels.kt` was regenerated by the generator; the generated model file
  is not hand-edited.
- Mutable Task/Event requests preserve fields not shown in the compact editor.
- Quick-note updates overwrite `ContentMarkdown` on the server. The legacy quick-HTML
  editor is read-only to avoid converting/replacing its HTML representation; lifecycle
  actions preserve server content. Text edits of ordinary notes retain attachment IDs,
  while metadata remains server-authoritative.
- Workbench reads and mutations are bound to the owner/server identity and monotonic
  session generation captured by the load. A delayed response or stale editor action
  cannot populate or mutate a different account; the user must explicitly refresh.
- Confirmation UI uses only pending-list/detail/reject operations from the OpenAPI
  snapshot. It projects a bounded summary and status/risk/timestamps; raw payload,
  preview, object IDs, audit IDs, and correlation IDs are excluded. Sensitive patterns
  in summaries are redacted. Confirm/strict-confirm actions are intentionally absent
  until the server provides a safely renderable preview contract.
- Habit UI uses only the contract list and archive operations. It omits free-form
  description/source fields, uses the contract cadence codes, and sends no inferred
  occurrence status or duration. Archive requires an explicit native confirmation;
  create/edit/check-in and reports remain outside this native slice.
- Outlook mirror events are shown but direct mutation is blocked; Outlook uses
  its dedicated sync/write-back contract.

## Verification boundary

The M5 source phase uses JVM tests and contract generation checks. No physical
device, ADB, AVD, production database, private data, or credentials are used.
Heavy Gradle verification requires the shared build slot and is reported
separately from source-level checks.
